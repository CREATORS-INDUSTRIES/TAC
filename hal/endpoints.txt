hal — endpoints (http://172.20.10.6:8080)

STATE

  curl "http://172.20.10.6:8080/state"
    position + motor (direction, speed, busy) + t. "/" is the same.

  curl "http://172.20.10.6:8080/position"
    position only, 0.0-1.0.

MOVEMENT

  curl "http://172.20.10.6:8080/move?to=0"
    closed loop to `to` (0.0-1.0). Blocks until it gets there or times out. 409 if the motor is busy.

  curl "http://172.20.10.6:8080/drive?dir=forward&speed=0.5&ms=200"
    raw push, stops by itself after ms.
    dir = forward|backward (def forward), speed def 0.5, ms def 200 (clamp 1-1000).
    409 if busy.

  curl "http://172.20.10.6:8080/stop"
    stops the motor, cancels drive's auto-stop.

SCREEN

  curl -X POST --data-binary @logo.svg "http://172.20.10.6:8080/screen?threshold=128&dither=false&invert=false"
    body = SVG, drawn centered. Optional query (values = defaults).
    use --data-binary, not -d. Max 64KB. 503 with no screen, 400 if the SVG is invalid.

SERIAL MODE

  controller --mode serial [--device /dev/serial0] [--baud 115200]
    same API over a serial port (8N1, no flow control). Default is still --mode http.
    at boot: ExecStart=/usr/local/bin/tac-firmware /usr/local/bin/controller --mode serial
    in serial mode tac-firmware skips netplan/IP/fader gesture: logo and straight to the controller.

  request: one line "GET <path>"              e.g. GET /move?to=0.3
           or "POST <path> <len>" + len bytes  e.g. POST /screen?invert=true 1834  then the SVG
  response: one line "<code> <json>"          e.g. 200 {"position":0.31,...}

  picocom -b 115200 --omap crlf --echo /dev/ttyUSB0    and type GET /state

  serial only (not available over HTTP):
  POST /update?name=controller|tac-firmware|service&crc=<crc32> <len>
    replaces the installed file (writes .new and renames). 400 if the crc doesn't match.
  GET /restart
    daemon-reload and exit; systemd relaunches tac-firmware.
  GET /console
    hands the port to a login (agetty). When the session ends (exit/Ctrl-D) the firmware comes back.
    don't run systemctl restart tac-firmware from that shell: you kill your own session.

  serial deploy: ./tac-firmware/deploy.sh /dev/cu.usbserial-XXXX    (BAUD=... if not 115200)

EVENTS (serial only)

  GET /subscribe?events=manual,motor,position,screen&hz=100
    no events = all. hz 1-200 (def 100) = max position events per second.
    only emitted on change; a still fader sends nothing.
  GET /unsubscribe
    off at boot and when the other end hangs up.

  event lines start with "@ ", responses with "<code> ":
  @ {"event":"manual","phase":"start","position":0.30,"t":...}       hand moves the fader with the motor stopped
  @ {"event":"manual","phase":"end","position":0.42,"t":...}         still for 150ms
  @ {"event":"position","position":0.41,"source":"manual|motor","t":...}
  @ {"event":"motor","phase":"start","cmd":"move","target":0.8,"t":...}
  @ {"event":"motor","phase":"start","cmd":"drive","direction":"forward","speed":0.5,"ms":200,"t":...}
  @ {"event":"motor","phase":"end","position":0.80,"t":...}
  @ {"event":"screen","w":128,"h":64,"bitmap":"<base64>","t":...}    after every successful POST /screen
    bitmap = whole screen, 1 bit/pixel, rows top to bottom, 16 bytes/row, MSB = leftmost pixel
